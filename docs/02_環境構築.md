# 環境構築（当日手順）

ハッカソン当日に、**アプリを自分のパソコンで動かす**ところまでの手順です。
上から順にコピペしていけば動きます。

> 🎯 ゴール：**Chrome でアプリが起動する**こと。ここまで来たら準備完了です！
>
> 事前に用意しておくもの（VS Code・Chrome・Git・GitHub アカウント）は
> 👉 [事前準備ガイド](01_事前準備ガイド.md) を参照。

## ステップ1：Flutter を入れる

**Windows でも Mac でも同じ手順です。** VS Code の拡張機能を使って入れます。

> すでに入っている人は飛ばしてOK。確認方法 ↓
>
> ```bash
> flutter --version
> ```
>
> バージョンが出れば入っています。

### 1-1. VS Code に Flutter 拡張機能を入れる

1. VS Code を開く
2. 左の四角いアイコン（拡張機能）をクリック
3. 検索欄に **「Flutter」** と入力
4. 一番上に出てくる **「Flutter」**（Dart Code 作）を **「Install」**

### 1-2. Flutter SDK をダウンロードする

1. `Cmd + Shift + P`（Windows は `Ctrl + Shift + P`）でコマンドパレットを開く
2. **「Flutter: New Project」** と入力して選択
3. 「Flutter SDKが見つかりません」というポップアップが出るので **「Download SDK」** を選ぶ
4. 保存先を聞かれたら、そのままデフォルトでOK（例：`~/development` や `C:\src\flutter`）
5. ダウンロードが終わるまで待つ（回線次第で数分〜10分程度）
6. 続けて「プロジェクト名」を聞かれますが、**今は不要なので `Esc` でキャンセルしてOK**
   （このあとステップ2で自分たちのリポジトリを使うため）

### 入れ終わったら

VS Code の **ターミナル**（メニューの「Terminal」→「New Terminal」）を開いて確認します。

```bash
flutter doctor
```

✅ いくつか緑のチェックが出ればOK。
`[!]` マークが出ても、Chrome が使えていれば問題ありません。

> ⚠️ `flutter` コマンドが見つからない場合は、一度 VS Code を閉じて開き直してから
> もう一度ターミナルで試してください。

## ステップ2：チームのリポジトリを作ってクローンする

テンプレートを **Fork（フォーク）** して、**チーム専用のリポジトリ**を作ります。
Fork は GitHub 上でリポジトリをコピーする機能で、複雑な git 操作なしに自分のリポジトリが作れます。

### 2-1. git が入っているか確認する

```bash
git --version
```

バージョンが出ればOK。出ない人は入れます。

- 🍎 Mac：`brew install git`
- 🪟 Windows：[git公式ページ](https://git-scm.com/download/win) からインストール

### 2-2. 代表者がリポジトリをForkする（チームで1人だけ）

> **この作業は代表者1人だけ**です。他のメンバーは [2-3](#2-3-他のメンバーはクローンする) まで待ってください。

#### ① GitHub上でテンプレートをForkする

1. [テンプレートのリポジトリ](https://github.com/HANAUTA/Hanauta_hackathon) を開く（ログインしておくこと）
2. 右上の **「Fork」** ボタンをクリック

   > 🖼️ **（画像予定）** 右上の「Fork」ボタンの位置

3. 「Repository name」をチーム名などに変更する（例：`team-alpha-hanalog`）
4. Owner は自分の個人アカウントのままでOK
5. **「Create fork」** をクリック

数秒で `https://github.com/<自分のGitHubユーザー名>/<リポジトリ名>` が作られます。

#### ② ローカルにクローンする

```bash
git clone https://github.com/<自分のGitHubユーザー名>/<リポジトリ名>.git
```

```bash
cd <リポジトリ名>
```

```bash
flutter pub get
```

```bash
code .
```

VS Code でこのフォルダが開きます。

> ⚠️ 何も起きない場合は、VS Code を開いて **「File」→「Open Folder」** から
> このフォルダを手動で開いてください。

#### ③ チームメンバーに書き込み権限を渡す

Public リポジトリなので**誰でも clone（読み取り）はできます**が、
**push（書き込み）できるのは代表者本人だけ**です。このままだと他のメンバーが push できません。

1. 作ったリポジトリの **「Settings」** → 左メニューの **「Collaborators」**
2. **「Add people」** をクリック
3. チームメンバーの **GitHub ユーザー名** を1人ずつ入力して招待

   > 招待された側にはメールか通知が届きます。**承認するまで push できません**。
   > 事前準備の段階で招待しておくと当日スムーズです（[事前準備ガイド](01_事前準備ガイド.md)参照）。

> これを忘れると、メンバーが `git push` した瞬間に権限エラーで止まります。

### 2-3. 他のメンバーはクローンする

代表者から共有された **チームのリポジトリ URL** を使います。
Public リポジトリなので、この時点では招待の承認前でも clone 自体はできます。

> 🖼️ **（画像予定）** リポジトリページの緑色の「Code」ボタンを押すと、
> clone 用の URL をコピーできます（代表者がこの URL をチームに共有します）。

```bash
git clone https://github.com/<代表者のGitHubユーザー名>/<リポジトリ名>.git
```

```bash
cd <リポジトリ名>
```

```bash
flutter pub get
```

```bash
code .
```

VS Code でこのフォルダが開きます。

> ⚠️ 何も起きない場合は、VS Code を開いて **「File」→「Open Folder」** から
> このフォルダを手動で開いてください。

> ⚠️ 自分の変更を `git push` しようとして権限エラーになる場合、
> 代表者からの Collaborator 招待を承認したか確認してください
> （GitHub の通知またはメールに届いています）。

## ステップ3：アプリを起動する

### 3-1. 設定ファイルを作る

VS Code の **ターミナル**（メニューの「Terminal」→「New Terminal」）で実行します。

```bash
cp .env.example .env
```

### 3-2. 配られた接続情報を貼る

運営から **Supabase の URL と Key** が配られます。
`.env` ファイルを VS Code で開いて、配られた値を貼り付けてください。

```
SUPABASE_URL=https://xxxxxxxx.supabase.co
SUPABASE_ANON_KEY=eyJhbGciOi...（長い文字列）
```

> ⚠️ **ブラウザのアドレスバーの URL ではありません！** 配られたものをそのまま貼ってください。
>
> 🔑 `.env` には大事な情報が入るので、GitHub には上がりません（設定済み）。

### 3-3. 起動！

```bash
flutter run -d chrome
```

Chrome が立ち上がってアプリが表示されたら成功です🎉

**ここまでで「全員がアプリを起動できる」ゴール達成です！** 🏁

## 困ったときは

| こんな症状 | こうする |
|---|---|
| `flutter` コマンドが見つからない | VS Code を閉じて開き直し、もう一度ターミナルで試す（ステップ1） |
| `git clone` でアクセスできない | リポジトリの URL が間違っていないか確認（ステップ2） |
| メンバーが `git push` で権限エラーになる | 代表者からの Collaborator 招待を承認したか確認。まだなら代表者に「③ チームメンバーに書き込み権限を渡す」を済ませてもらう |
| 起動したらエラー画面が出る | `.env` の URL・Key が正しいか確認（ステップ3） |
| ログインできない | 運営に連絡 |
| `agy` コマンドが見つからない | [Antigravity CLI 利用ガイド](09_Antigravity_CLI利用ガイド.md) のインストール手順を確認（ステップ4） |

スマホで確認したい人は [GitHub Actions 設定手順](06_GitHub_Actions設定手順.md) も見てください。
