# 開発の流れ

アプリが起動できたら、いよいよ開発です。
ブランチを作って開発し、`main` にマージする、という流れで進めます。

```
① ブランチを作る → ② Chrome で開発 → ③ push → ④ main にマージ
```

> **大事なルール：`main` に直接コミットしない。**
> 自分のブランチで作業 → main にマージ、の流れで進めます。
> ここを飛ばして全員が `main` に直接 push すると、コンフリクト（変更のぶつかり合い）が起きます。

---

## ① ブランチを作る

```bash
git checkout -b 自分の名前
```

例：`git checkout -b taro`

## ② Chrome で開発する

```bash
flutter run -d chrome
```

Chrome が立ち上がり、`flutter run` を実行した**ターミナルはそのまま起動し続けます**
（プロセスが終わらず「待機中」の状態になります）。以降はこのターミナルに向かって
キーを打つことで、アプリを操作できます。

コードを保存すると、多くの場合は自動でブラウザに反映されます（hot reload）が、
反映されないこともあります。そんなときは、**そのターミナルを選択した状態で**次のキーを押します。

| キー | 名前 | 効果 |
|---|---|---|
| `r` | Hot Reload | 変更した部分だけ素早く反映（今の画面や入力内容はそのまま） |
| `R`（大文字） | Hot Restart | アプリを最初からやり直す（ログイン状態や入力内容もリセットされる） |
| `q` | Quit | アプリを終了する |

> 💡 見た目を変えただけなら `r`、`main.dart` や Provider の初期化処理を変えたときや
> 「変更したのに反映されない」ときは `R` を試してください。
> それでも直らない場合は `q` で一度終了し、`flutter run -d chrome` からやり直しましょう。

## ③ 自分のブランチに push する

```bash
git add .
git commit -m "変更内容をここに書く"
git push -u origin 自分のブランチ名
```

> 2回目以降は `git push` だけでOK。
>
> 🔑 初めて push するとき、ログインを求められたら GitHub のユーザー名と
> **パスワードの代わりにアクセストークン（PAT）** を入力します。

## ④ main にマージする

```bash
git checkout main
git pull
git merge 自分のブランチ名
git push
```

> ⚠️ マージでエラー（コンフリクト）が出たら、無理に進めず運営に相談してください。

マージ後は自分のブランチに戻って作業を続けられます。

```bash
git checkout 自分のブランチ名
```

---

## まとめ：1サイクル

```bash
git checkout taro              # 自分のブランチで作業
flutter run -d chrome          # Chrome で開発

git add .
git commit -m "○○を修正"
git push                       # 自分のブランチに push

git checkout main
git pull
git merge taro
git push                       # main に反映

git checkout taro              # 戻って続きの作業
```

## 💡 Chrome で確認できること・できないこと

| 確認項目 | Chrome | スマホ実機 |
|---|---|---|
| 画面の見た目・操作 | ◎ | ◎ |
| ログイン・データ保存 | ◎ | ◎ |
| カメラ撮影 | △（制限あり） | ◎ |
| 動画の向き・表示 | △ | ◎ |

> カメラや動画の向きは Chrome だと正しく確認できないことがあります。
> 最終的な見た目はスマホ実機で確認しましょう。

## 🚀 もっと進めたい人へ：スマホでも自動的に見られるようにする

基本の開発サイクルは上記だけで完結します。ここから先は**余裕が出てきたチーム向けの発展項目**です。

実は、`main` に push するたびに**スマホのブラウザからもアプリを開けるようにする仕組み**が
このテンプレートには用意されています（[GitHub Actions 設定手順](06_GitHub_Actions設定手順.md)）。
代表者が最初に1回だけ設定すれば、以降は何もしなくても自動で反映されます。

必須ではないので、まずは Chrome での開発に慣れることを優先してOKです。
